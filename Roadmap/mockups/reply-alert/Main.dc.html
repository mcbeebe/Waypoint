A reply should never be buried
Owner report, 2026-10-08: a provider's reply landed in Paper Trail; Home showed only an overdue IHSS card.

What happens today

  • Home syncs Gmail on mount, and the server cron does it every 5 min. The reply was picked up (“Gmail checked 11:42 AM”).
  • Home shows one card from a fixed ladder: resume › crisis › overdue › reply › today… Any overdue plan action beats every reply.
  • There is no “read” state for a reply. A reply card only clears when you send an answer on the thread.
  • The reply push (native only) is generic and has no deep link, so tapping it just opens the app. On web there is no push at all.

Proposal (A, recommended)

  1. A “New reply” strip directly under the One Thing card whenever an unread reply exists that isn’t already the One Thing. The copy states the status (“Dana Reyes replied”) and never blames.
  2. “Read ›” opens Paper Trail with that reply expanded and highlighted. Paper Trail’s highlightId param already exists.
  3. Read state: opening a reply marks it read and clears the strip.
    • v1: stored per device (AsyncStorage), no migration. You could see it again on a second device.
    • Later: a communications.read_at column, which needs a migration and an owner review.
  4. Paper Trail: unread replies get a dot, and a “Replies (n)” filter chip is added next to Drafts.

Not in this change (flagged)

  • Synced replies are hard-coded organization: regional_center in the Gmail edge functions. That is why a provider’s reply shows as “Regional Center”. This is an edge-function change, so it waits for the owner.
  • A deep link on the reply push. This needs a native notification-tap listener.
  • The existing reply card says “the ball is in your court” even for an “I’ll get back to you” reply like this one.
