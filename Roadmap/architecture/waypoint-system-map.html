Waypoint System Map

How a parent moves through the app, and what happens behind them. Waypoint is a navigation platform for California families raising children with disabilities — it has to know that a requested IPP review starts a 30-day statutory clock under W&I Code §4646.5(b), and that a signed assessment consent starts a 60-day one under Ed Code §56344. Most of the architecture below exists to keep those clocks, and the paper trail that proves them, correct.

Part I · Front end

The shell decides who you are before it decides what you see

App.tsx is a single ordered fork. Every branch is exclusive, and the order is load-bearing — two of the six rungs exist because getting the order wrong put the wrong person in the wrong product.

Above the navigator, the tree wraps in providers that every screen assumes: ErrorBoundary → I18nProvider (en/es/vi) → TextScaleProvider → ToastProvider → SafeAreaProvider → WebFrame, with a NetworkBanner above the NavigationContainer. Linking config gives nearly every screen a URL, so browser back/forward works on web and waypoint:// deep links work on native. Two screens (Thread, DocumentAnalysis) are deliberately pathless — their params aren't serializable.

Onboarding is six gated questions

OnboardingFlow.tsx holds one wizard with TOTAL_STEPS = 6, each with its own validity predicate — Next stays disabled until the step is answerable. The answers become the families and children rows that every later screen reads, which is why the flow is short and none of it is optional.

StepAsksBecomes
0Parent name, child nameIdentity for every letter and draft
1DiagnosesEligibility reasoning, KB routing
2BirthdayAge-triggered clocks — Early Start exit at 3, transition planning at 16
3Regional Center statusWhich Lanterman track applies
4IEP statusWhich IDEA track applies
5InsuranceAppeal path — commercial, Medi-Cal, or CCS

The navigator is generated from a data file, because hand-mirroring it shipped nine dead taps

React Navigation resolves a navigate by walking to parents, never to a sibling stack. A target is reachable only if the caller's own stack registers it, or the call names the tab that does. Get it wrong and the tap does nothing — silently, in production, with CI green.

So src/navigation/routeGraph.ts declares the graph as data, MainTabs.tsx builds the navigator by mapping over it, and the tests read the same structure. A screen not in the file does not exist; a screen in the file is registered by construction. The first attempt at a guard — a hand-copied list of route names in a test — drifted immediately and certified nine dead taps, because it encoded what its author believed rather than what the navigator does.

Home is a decision, not a dashboard

src/lib/homeTriage.ts ranks everything Waypoint knows and returns the one thing to lead with, plus the queue behind it. The ladder is a genuine ranking — fixed, published, and the same every day — so it is the rare list that earns its numbers.

  1. resumeSomething half-finished is still open
  2. crisisSafety or a service about to lapse
  3. overdueA statutory clock has already run out
  4. replyAn agency answered and no one has read it
  5. todaySomething is scheduled for today
  6. clockA deadline is running but not yet blown
  7. questionWaypoint needs one fact to proceed
  8. opportunitySomething this family likely qualifies for

Four rules, each written after a 20-persona audit found the failure it prevents:

  • One published order. Show the highest thing that is true right now — never a guess about what the family cares about today.
  • Provenance, not praise. Every kicker says what class this is and where it came from (“NEW REPLY — RECEIVED YESTERDAY”), never “Waypoint noticed”. The same eyebrow on contradictory cards is what made them read as contradictory.
  • Never assert without evidence. A class only appears when its evidence exists; an opportunity carries its citation and its “because you told us…” reason.
  • Deferral is honest. “Not today” always states when the item returns, and set-aside items stay listed with Undo. The old permanent ✕ was the audit's sixth failure.
Owner rule — pinned by tests

Home states the status of the answer — “An answer on X is past due” — never an actor who failed (“They missed the deadline”). The framing a family reads first is the one they carry into the phone call, so it starts neutral and firms up only along the escalation ladder: collaborative → assertive → adversarial. Pinned in homeTriage.test.ts.

From “something is late” to a sent letter

The draft flow is the app's spine: it is what turns triage into an action an agency actually receives. useDraftFlow.ts is the engine; HomeScreen only renders it.

Escalation tone rule

Every letter template starts friendly — “ask” or “request”, never “demand” — and firms up only as asks go unanswered. The warm tone in ai-proxy hard-bans legal citations and caps the draft at 100 words; professional allows timelines under 250; strong permits surgical citations under 350. Two templates override this by design: a Notice of Action demand and a §4731 complaint stay firm even at warm tone, because a verbal denial is not a decision.

Part II · Back end

One client, one database, eight functions that hold secrets

The app talks to Postgres directly through PostgREST, carrying the user's own JWT. Authorization is row-level security in the database — not checks in app code. Anything that needs a secret, a service role, or a third party goes through an Edge Function instead.

Access is owner ∪ member, resolved by a function that cannot recurse

Waypoint's data was originally locked to the family owner: most tables read family_id in (select id from families where user_id = auth.uid()). Family Sharing added co-parents — and a co-parent with a valid membership row could open the app and see no child, no plan, no calendar, no documents.

The fix was additive. Every new policy is permissive and sits alongside the owner policy rather than replacing it, so existing access cannot regress — permissive policies OR together. Each resolves the family set through member_family_ids(), a SECURITY DEFINER function that runs as its owner and therefore never re-enters family_members' own policies.

Eight functions, three authentication stories

Five carry a normal Supabase JWT. Three deliberately do not — and each of those three has a comment in config.toml explaining why flipping it would break the caller, because the setting looks like a bug until you know.

Part III · Data flow

One Navigator turn, end to end

The sequence below is genuinely ordered — each step needs the one before it — so it is numbered. Retrieval runs on Postgres full-text search, not embeddings: the pgvector column and match_knowledge exist and are indexed, but the live path is match_knowledge_fts, which keeps the whole reasoning stack on one provider.

The loop that runs with the app closed

A family should learn an agency replied even if nobody opens Waypoint that week. That requires a path with no device in it at all — which means no user session, which means a service role and a shared secret.

Money moves in one direction

Checkout happens on Stripe-hosted Payment Links — the app never sees a card. The family id rides along as client_reference_id, and stripe-webhook is the only writer of self-paid entitlement rows, using the service role so RLS does not apply.

On the read side, resolveEntitlement applies one rule: a live grant makes the family Premium; no rows is the free tier. Sponsorship is a first-class case, and it labels itself honestly rather than hiding — “Included with your facilitation — you pay $0” — across four sponsor types (facilitation, district, employer, licensee). A sponsored grant wins the label even when a self-subscription also exists, so a family is never told they're paying for something someone else covers.

Part IV · Operations

What CI actually guarantees

Three blocking gates run on every PR touching waypoint-app/: npx tsc --noEmit, npm run lint, and npm test. A companion ci-guard.yml exists because the main workflow filters on paths, so a PR touching only docs would otherwise report no checks at all.

Four test projects, because one clock is not a clock

npm test runs four vitest projects, and the file count is not the run count — the two .tz.test.ts files execute twice, once per timezone.

projectEnvironmentWhy it exists
logicnodeThe pure modules — sorting, clocks, triage, entitlements
uijsdom + react-native-webThree reviews running found defects the logic suite structurally could not see: a button wired to a screen that didn't exist, a control a screen reader couldn't reach, a headline rendered as a 10px badge
tzAsia/Ho_Chi_MinhCatches a deadline computed a day early
tz-westAmerica/Los_AngelesCatches a day late — and this is where Waypoint's families actually are

Running only the eastern timezone once let actionSort bucket created_at on its UTC day for a full PR — invisible at UTC+7, an off-by-one every evening in California. A .tz.test.ts must pass in both, so its assertions cannot assume a sign.

Sharp edges worth knowing before you touch anything

Migrations are applied by hand

All 59 are run manually in the Supabase SQL editor, in order. scripts/build-pending-migrations.mjs bundles a range into one transaction. Code assuming an unapplied migration ships a silently broken feature — this has already happened once, and the fix commit is still in the history (e0bdcdd, “Fix empty calendar when migration 029 hasn't been applied”).

The edge functions are the least-verified code in the repo

All eight are excluded from tsconfig.json and have no tests — yet deploy-edge-functions.yml ships them to the production project on merge to main. Treat every change there as unverified by CI and test it by hand against a live project.

Two prompts must be edited together

The classifier prompt is duplicated in src/lib/ai.ts (classifyIntent) and scripts/prompt-regression.mjs, held together only by a “must mirror” comment. Change one without the other and the 78-case regression suite silently tests a stale prompt.

Not a bug

stripe-webhook, push-send and poll-replies are verify_jwt = false on purpose. Each has a caller that cannot present a Supabase JWT, and each proves itself another way — an HMAC signature or a timing-safe shared secret. Flipping any of them to true makes the caller silently 401.
